- **CSS constraint algorithm: `min-height`/`min-width` beat fixed `width`/`height` regardless of `!important`** (AI-585 / task-fc5060): `min-width` and `min-height` are SEPARATE CSS properties from `width` and `height`. The browser first resolves the cascade (including `!important`), then applies constraint phase rules where `min-size` always wins over computed `width`/`height`. This means `min-height: 44px` on a button with `height: 40px !important` (e.g. from `slider.css`) correctly produces a 44px button — no specificity battle needed, no `!important` on `min-height`. Use this for every WCAG 2.5.5 touch-target fix where a third-party library sets a fixed dimension with `!important`.
- **Vue SFC `<style scoped>` raises specificity beyond a plain class selector** (AI-724 / task-747f20): Vue SFC scoped styles compile to `[data-v-hash].class { ... }` — an attribute + class selector with specificity (0,2,0). External CSS files (e.g. `element-style-editor.css`, `live-edit-classes.css`) targeting `.class { ... }` have specificity (0,1,0) and always lose, even with compound selectors. Fix: add `!important` to the override declaration in the external CSS. Applies to all ESE dark-mode overrides that target components inside Vue SFC `<style scoped>` blocks (e.g. `.angle-top-left`, `.angle-top-right` in the border-section component).
- **iframe → parent postMessage row-count bridge pattern** (AI-761 / task-faf839): `Modules/MediaLibrary/resources/views/filament/admin/pages/media-library-page.blade.php` emits `window.parent.postMessage({ type: 'mw-filemanager:row-count', count: N }, '*')` where `N` is a PHP-rendered `$mwAi761Total` variable (server-side Eloquent count, never waits for Livewire boot). This avoids the skeleton being stuck forever and avoids an empty-state flash before the real count is known.

## Naming & Conventions
- PHP tests use PHPUnit 11 with `#[Test]` attributes; existing class-style tests prefer descriptive `it_*` method names.
- The repository’s broad PHP suites are defined in `phpunit.xml`, and the memory-safe full-suite runner is `./run-tests.sh`.
- Conventional Commits are already documented in `CONTRIBUTING.md` and used for task-by-task commits.

## Build & Run

### Install
- Requires PHP `^8.3` per `composer.json` (Laravel 11 minimum). Node 18+ for the Vite/Webpack pipelines.
- `composer install` — PHP dependencies.
- `npm install` — root JS dependencies (then per-package `npm install` under `packages/frontend-assets/`, `packages/frontend-assets-libs/`, `packages/microweber-filament-theme/`, `docs/` as needed; the root `package.json` does NOT auto-recurse).
- Copy `.env.example` → `.env`, run `php artisan key:generate`, configure DB credentials, then `php artisan migrate`.

### Development
- `php artisan serve` — local PHP dev server (default `http://127.0.0.1:8000`). Production typically uses Apache/nginx in front of `public/index.php`.
- `npm run dev` (root) — orchestrates per-package dev/watch builds via `run-dev.js`.
- Per-package dev builds (scoped, faster):
  - `cd packages/frontend-assets && npm run dev` (Vite watch).
  - `cd packages/microweber-filament-theme && npm run dev` (Webpack watch).
- VitePress docs preview: `cd docs && npm run docs:dev`.

### Production / one-shot build
- `npm run build` (root) — orchestrates production builds across all packages via `run-build.js`.
- Per-package production builds:
  - `cd packages/frontend-assets && npm run build` (Vite).
  - `cd packages/microweber-filament-theme && npm run build` (Webpack).
- VitePress docs production build: `cd docs && npm run docs:build`. Must stay green; targeted `ignoreDeadLinks` patterns in `docs/.vitepress/config.js` whitelist filesystem-pointer refs (`../../Modules/`, `.php`, etc.) so real dead-link detection still catches new ones.
- After editing anything under `packages/<pkg>/resources/**` (Vue, SCSS, CSS, JS, TS), rebuild that package — the running app serves the built bundle, not source.
- `cd packages/<pkg>` (or any subdir) leaves the shell CWD in that subdir for subsequent commands. For later `git`, `npm`, or tool calls in the same dispatch, prepend `cd /home/headless/Documents/GitHub/microweber && ...` or use absolute paths — otherwise pathspecs fail with `did not match any files`.

### Tests
- `composer test` — main PHPUnit run.
- `./run-tests.sh` — split-process runner that groups suites separately (avoids the ~6 MB/test memory leak).
- `vendor/bin/phpunit --filter=<ClassName>` — run a single test class (fast iteration on contract tests).
- `vendor/bin/phpunit tests/Feature/<File>.php` — run a single file.
- Test DB is MySQL `microweber_testing` (real DB, not sqlite, not mocked); kill any prior PHPUnit run before starting a new one.

### Operational
- `php artisan migrate` — apply core + module migrations.
- `php artisan queue:work` — process background jobs.
- `php artisan schedule:run` — invoked by a system cron each minute.
- Admin password reset for local dev (Apache `/admin/login` 404 quirk gotcha forces this for Playwright runs against `php artisan serve`): `php artisan tinker --execute='\App\Models\User::where("email","admin@example.com")->first()->update(["password"=>bcrypt("admin")])'`. Used 2026-05-16 / task-f4bf24 to onboard agent-designer.

## Gotchas & Known Issues
- The local Apache-served runtime in this environment returns `404` for `/admin/login` even though `http://127.0.0.1` responds with `200`, so browser verification can fail for environment reasons rather than app regressions.
- The full PHP test surface is intentionally split by `run-tests.sh` because long single-process runs hit PHP memory fragmentation/OOM issues (~6 MB/test leak).
- The root repo now documents PHPUnit + `run-tests.sh` as the active entrypoints; the remaining Pest helper files under `docs/testing/` are optional scaffolding only, not live root configuration.
- Live-edit theme helpers must stay scoped to `.mw-admin-live-edit-page`; unscoped Filament tab/input/modal overrides leak into unrelated admin screens and create recurring visual regressions.
- No global `[x-cloak] { display: none }` rule exists. Alpine paints once before init, so any element with text bindings flashes literal `""`. Use inline `style="display: none;"` defaults for empty states instead of relying on `x-cloak`.
- Bash heredoc appends to CSS files have produced reproducible mid-stream duplications. Append via the `Edit` tool with `old_string` = existing file tail, `new_string` = tail + new block.
- `->modalCancelAction(false)` is not the correct Filament API — use `->modalCancelActionLabel('Cancel')`.
- Filament RichEditor renders into `[contenteditable=true]` inside `.fi-fo-rich-editor` / `.ProseMirror`; it does NOT bubble plain `input` events reliably. Listen on `input` + `keyup` + `blur` together when watching for content changes.
- Do not use PHPUnit `RunInSeparateProcess`, `DatabaseTransactions`, or `RefreshDatabase` traits, and never run tests in parallel — the suite is not safe under those modes.
- Window-event handler names registered between admin frame and iframe must match exactly on both sides (`liveEditSaveCallMountedAction`, `liveEditUndoLastPublish`, `liveEditInsertLayoutRequest`). Adding a new verb means editing both files.
- VitePress + Vue interpolation: `{{ expression }}` in markdown prose or inline backticks (outside fenced code blocks) is parsed by Vue at SSR. If the expression isn't a real method on the rendering context, `npm run docs:build` fails with `TypeError: _ctx.<x> is not a function`. Escape with `&#123;&#123; expression }}`. Fenced ```code blocks``` are safe.
- VitePress `ignoreDeadLinks` regex patterns must accept the `./` prefix that nested pages emit — don't anchor with `^`. Whitelist filesystem-pointer paths so real dead-link detection still catches new ones.
- Sitemap previously had an unconditional `return true;` at the top of `needToUpdateSitemap()` that bypassed the 3hr TTL and forced regeneration on every request. Fixed (commit 7386606cd1) and pinned by a contract test that re-fails if the short-circuit returns.
- Filament `Action::make()->color('success')` rendered with `size=lg` (e.g. "Place Order") applies inline styles that beat normal CSS selectors — enforcing `min-height` requires `!important` on `button.fi-btn.fi-color-success`. Discovered AI-517.
- JIRA queue drift: PM's view can run 1–4 cycles behind on-the-ground state when ship cadence exceeds queue-refresh interval. Observed 3+ times in a single session (AI-322..AI-335 tier-1 docs; AI-326 hardening; AI-510..AI-515 Phase 1 UX). Mitigation: status-correction reply with ship-table + commit hashes + JIRA-refresh recommendation, no defensive tone.
- CSS class collision footgun: `.mw-empty-state-cta` is owned by `DashboardEmptyStateWidget` (`microweber-theme-v3.scss`); naming a new button class the same is silently overridden in the cascade. The render appears correct visually until `getComputedStyle` shows the wrong background. Always grep `packages/` for the proposed class name before adopting it.
- Bare `#toolbar { flex-wrap: nowrap }` rule does NOT apply on mobile — `.mw-(admin-)?live-edit-page #toolbar` inside `live-edit-mobile.css` `@media (max-width: 768px), (pointer: coarse)` wins. Mobile-only toolbar fixes must live in `live-edit-mobile.css`.
- Reproducing a UX bug requires the correct viewport. Initial measurement at 1440px during task-74c5f5 showed no overlap; reproducing required resizing Playwright to ~560×440 to match the user's screenshot before the root cause (mobile-specific `flex-wrap: wrap` rule) became visible.
- Live Edit toolbar back-compat hooks asserted by `tests/Browser/AdminLiveEditDropdownAndButtonsTest.php`: `#toolbar-user-menu-button`, `#user-menu-wrapper`, `#user-menu nav`, `.mw-le-hamburger`, "Dark mode"/"Light mode" text. Removing any breaks the Dusk suite. Use `style="display: none;"` to keep the DOM hook while removing the visual rendering.
- **Filament v5 inline-`<style>` grid override in server-rendered forms** (AI-870 / task-30040a): Filament v5 renders an inline `<style>` block alongside each `SchemaComponent` that applies `@media (min-width: 640px) { .fi-sc-component .mb-6 { display: grid; grid-template-columns: 1fr 1fr } }`. Any wrapper `<div>` carrying class `mb-6` inside `.fi-sc-component` becomes a 2-column grid at ≥640px regardless of intent. Fix: add `display: flex !important; flex-direction: column !important;` in the Webpack-bundled CSS at a selector that beats the inline style (which has specificity 0-2-0). Can only be caught at runtime — source-level tests pass because the inline style is rendered server-side and absent from the static PHP/Blade source under test. Pair with a Tier-1 bundle probe to confirm the override is served.
- **Vue SFC scoped styles can only be overridden from external CSS with `!important`** (AI-724 / task-747f20): the Vue SFC `<style scoped>` compiler appends a `[data-v-XXXX]` attribute to every rule, raising specificity to (0,2,0) or higher. Any external stylesheet targeting the same class at (0,1,0) loses regardless of source order. Always add `!important` to external ESE/live-edit-classes.css overrides that target components with scoped styles (e.g. `.angle-top-left`, `.angle-bottom-right`, `.reset-field` in `element-style-editor.css`).
- **Broad Tailwind utility class CSS fix risks hitting multiple sibling elements** (AI-881 / task-ba0702): Tailwind utilities like `p-2` are used semantically (padding 8px), not by surface. A CSS rule `.p-2 { min-height: 44px }` targeting a button would also apply to any `<h3 class="... p-2">` or `<p class="... p-2">` siblings in the same component. When a dispatch suggests targeting a shared utility class, grep the same template file for other uses of the class first. If other non-interactive elements use it, prefer a Blade template change (add a specific class OR change to a larger padding utility) over the global CSS rule.
- **`git add -f` required for Bootstrap screenshot subdirectory** (AI-873 / task-2026-05-21-3d7892): `Templates/Bootstrap/resources/assets/img/screenshots/` is nested inside a `.gitignore` pattern (the glob that suppresses untracked binary blobs) even though `Templates/Bootstrap/` itself is tracked. Plain `git add` refuses with "ignored by .gitignore"; use `git add -f Templates/Bootstrap/resources/assets/img/screenshots/...`. Verify the parent template is actually tracked first via `git ls-files Templates/Bootstrap/` before using force-add — you're adding to microweber's tree, not a subrepo. Contrast: `Templates/Big2/` IS a separate git repo AND gitignored; adding its files to microweber is wrong.
- `Templates/<X>/` directories (e.g. `Templates/Big2/`) are gitignored at `.gitignore:94` and are **separate git repositories** in their own right. Edits inside `Templates/Big2/` MUST be committed inside `Templates/Big2/`'s own git history — never force-add to microweber via plumbing. Practical effect: a fix that lands only in a gitignored template (per AI-531a) does NOT persist to fresh microweber clones; the long-term solution is to migrate the affected CSS/asset to a non-gitignored location (`packages/frontend-assets`, `Templates/Bootstrap/`).
- Tailwind v4 dual-property `translate` + `transform`: Tailwind v4 utilities like `-translate-x-full` compile to the native CSS `translate: -100% !important` property — NOT `transform: translateX(...)`. Overriding only `transform` in a project rule silently fails because CSS `translate` is a separate property that wins. Symptom: element appears off-screen even though DevTools shows `transform: matrix(1,0,0,1,0,0)`. Fix: reset BOTH properties (`translate: none !important; transform: translateX(...) !important;`). Reference: `src/MicroweberPackages/Filament/.../live-edit.blade.php` `.fi-sidebar` rule (task-2026-05-16-02760c, commit `3d5baca3b1`).
- Alpine `x-data="..."` attribute corruption: `/* … */` block comments inside `x-data` that contain literal `"` characters terminate the HTML attribute at the first embedded `"`, silently corrupting the entire x-data block. Cascade of `q is not defined` / `hasVisibleCardsInGroup is not defined` errors follows. Reference: `add-content-modal.blade.php` regression-guard test `comment_block_uses_single_line_comments_only_in_xdata` (task-2026-05-16-968a71). **Update 2026-05-17 (AI-790):** the same parser quirk hits `//` line comments containing quoted prose (e.g. `// when typing "page" the filter…`) — the in-place "use `//` only" workaround is fragile. Robust fix for any long Alpine x-data: extract to `Alpine.data('factoryName', () => ({...}))` registration in a separate `<script>` block + reference via bare `x-data="factoryName"`. - Stage-1 data-shipped-consumer-not-wired (AI-788 CHANGE / task-2026-05-17-6027b9): every layer of contract test passes — the data source ships, the DataProvider verifies the values are well-formed, the source-side enum carries actionable copy — but the user sees zero description nodes because the consumer call is `// ->descriptions(...)` (commented out) at the site that mounts the data into the UI (e.g. `ListCustomFields.php:266`). - Long Alpine `x-data="..."` must be extracted to `Alpine.data('factoryName', () => ({...}))` registration once it crosses any of these thresholds: >10 LOC, contains any comments, or contains any embedded `"`. The HTML attribute parser is the limiting factor; extracting to a factory removes attribute-escape concerns entirely. Reference: AI-790 / `add-content-modal.blade.php`.
- PHP docblock prose containing a literal `*/` terminates the docblock prematurely. Cure: rewrite as words (e.g. "slash-star ... star-slash style block comment") rather than reproducing the actual characters. Same family as the x-data quote bug — sequences that have meaning to parsers must not appear in prose inside those parsers.
- Vuetify CSS is NOT loaded in the parent Microweber admin window — only inside iframe/canvas surfaces that bundle it. ## Dependencies (non-obvious)
- `nwidart/laravel-modules` powers the feature-module layout under `Modules/`.
- Filament 5 + Livewire 4 drive the admin UI and many live-edit flows.
- Root frontend asset builds are orchestrated through `run-build.js` and package-level build scripts.
- `packages/frontend-assets/` builds with Vite; `packages/microweber-filament-theme/` builds with Webpack. The two are not interchangeable.
- `packages/frontend-assets/` holds project-authored Vue/SCSS/CSS/JS; `packages/frontend-assets-libs/` is a sibling vendor-bundle for third-party libraries (e.g. `@mdi/font`) built via its own `build.mjs`. Don't confuse them — new application code goes in `frontend-assets`, not `frontend-assets-libs`.
- VitePress (under `docs/`) is the documentation site engine.
- Locale-aware UI relies on `MultilanguageHelpers` + per-locale `ModuleOption` rows — no separate i18n library; admin URL locale switch lives at `/admin/lang/{locale}`.
- The `public` storage disk (`storage/app/public` symlinked to `public/storage`) is the canonical home for uploaded media; `Media::create(['filename' => Storage::disk('public')->url($path), ...])` is the canonical insert shape.

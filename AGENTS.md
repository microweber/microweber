# Microweber — Project Knowledge

> Project-specific patterns and pitfalls learned across recent tasks. Kept in sync across `.github/copilot-instructions.md`, `CLAUDE.md`, and `AGENTS.md`.

## Project Identity
- Microweber CMS — modular PHP CMS on Laravel 11.
- Active development branch: `filament-5`. Main remote branch: `master`.
- Admin UI: Filament v5 panels (`admin`, `checkout`). Public surface served by Laravel + Microweber templates.
- Live Edit toolbar: Vue 3 SFCs under `packages/frontend-assets/resources/assets/ui/components/Toolbar/`.
- Modal layer: Livewire v4 (`src/MicroweberPackages/Livewire/resources/views/mw-modal.blade.php` is the generic wrapper) + bespoke `mw-*` modals.
- Documentation site: VitePress under `docs/` (per-module pages at `docs/modules/<name>/`).
- Translations: `MicroweberPackages\Multilanguage\MultilanguageHelpers` gates locale-aware UI.

## Architecture Rules
- Three top-level source roots:
  - `src/MicroweberPackages/<Pkg>/` — core packages (PHP + Filament + Blade + Livewire).
  - `Modules/<Name>/` — pluggable modules (Content, Product, Category, Media, Cart …). Filament resources live under `Modules/<Name>/Filament/Admin/<Resource>/Pages/`.
  - `packages/<pkg>/` — build-managed bundles (Vue/SCSS/CSS/JS). `frontend-assets/` uses Vite; `microweber-filament-theme/` uses Webpack.
- Product `extends` Content. Cart is a state manager over Content/Product rows — NOT a separate data owner.
- Content fields: `content_body` and `content` both hold the rendered HTML on Page/Post. Use `setCustomField` / `setContentData` for arbitrary metadata.
- Live Edit bridges two surfaces:
  - Admin frame: `src/MicroweberPackages/LiveEdit/Filament/Admin/Pages/AdminLiveEditPage.php`.
  - Canvas iframe: `src/MicroweberPackages/LiveEdit/resources/views/iframe-page.blade.php`.
  - They communicate via `window.dispatchEvent(new CustomEvent('<verb>'))` — registered handler names: `liveEditSaveCallMountedAction`, `liveEditUndoLastPublish`, `liveEditInsertLayoutRequest`. Add new handlers in **both** files (admin frame dispatches, iframe listens, or vice versa).
- mw-modal focus contract (AI-240): focus-trap with stack, Escape closes, focus returns to opener. Never break or bypass — additions like the close-X must filter themselves out of *initial* focus selection while staying in the Tab cycle.
- Admin/checkout color tokens come from `MicroweberPackages\Filament\Themes\MwColors`. Primary blue is Bootstrap `#0d6efd` across admin + checkout + public. Use `MwColors::Blue`, never `Color::Blue`.
- CSS token chain: `--color-product-title` → `--color-text-primary`. Override at the token, not per-template, for cross-surface unification.
- Filament `body.fi-panel-admin` is the scope handle for admin-wide overrides. `body.fi-panel-checkout` is the equivalent for checkout. `body.fi-panel-profile` scopes the customer Profile panel (`Modules/Profile/Providers/FilamentProfilePanelProvider.php`, path `/profile`, panel id `profile`). RTL is `[dir="rtl"]` (already emitted by `lang_attributes()`).
- Touch-target CSS is split across **two build pipelines** based on which surface owns the rendered HTML: public-template HTML → `Templates/Bootstrap/resources/assets/css/public-touch.css` (Vite, served from `public/templates/bootstrap/css/public-touch.css`); Filament-panel HTML → `packages/microweber-filament-theme/resources/assets/css/microweber/mobile-touch.css` (Webpack, served from `public/vendor/microweber-packages/microweber-filament-theme/build/...`). A mobile-audit fix may need rules in BOTH (see AI-518 Profile + header pattern).
- Admin settings pages extend `MicroweberPackages\Admin\Filament\Pages\AdminSettingsPage` — save is Livewire-reactive (no submit action required by the subclass).
- `MicroweberPackages\Filament\Support\FilamentRegistry` is the plugin-driven entry point for registering pages, resources, widgets, and plugins on the admin panel.
- LiveEdit canvas has 3 concurrent forms; save-flow specificity (highest priority wins): `callMountedTableBulkAction` > `TableAction` > `FormComponentAction` > `Action` (mountedAction).
- Sitemap freshness gate (`Modules/Sitemap/Http/Controllers/SitemapHelpersTrait.php::needToUpdateSitemap()`) rebuilds only when the file is missing, unreadable, or older than 3 hours. Never re-introduce an unconditional `return true;` at the top.
- Tier-1 narrative docs live at `docs/modules/<name>/` for 9 modules (product, cart, checkout, order, search, seo, sitemap, admin, liveedit). Six pages each: index/installation/usage/api/examples/troubleshooting. Landing page: `docs/modules/README.md`.

Mobile fix MUST live in `live-edit-mobile.css` with `flex-wrap: nowrap !important` + `overflow-x: auto !important` + `flex-shrink: 0` on toolbar children — otherwise dropdowns wrap to a second row and overlap the iframe canvas at narrow viewports (task-2026-05-16-74c5f5).

## What NOT to Do
- Do NOT use `RunInSeparateProcess`, `DatabaseTransactions`, or `RefreshDatabase` in tests. Do NOT run tests in parallel.
- Do NOT rely on a global `[x-cloak] { display: none }` rule — the project has none. Use inline `style="display: none;"` defaults for empty states.
- Do NOT echo the user's typed query back in empty-state copy ("No results for X") — Alpine renders before paint and you see literal `""`. Keep empty-state strings static.
- Do NOT skip the build after editing `packages/<pkg>/resources/**` — the served bundle won't include your change.
- Do NOT invent emails or `@local` aliases — only addresses listed in `.autodev/CONTRACTS.md` are valid.
- Do NOT delete `[x]` rows from `TODO.md` mid-session — archive to `DONE.md` only on scope change.
- Do NOT sweep `text-align: left/right` → `start/end` (or similar large mechanical refactors) without RTL test content or an explicit dispatch — high regression risk.
- Do NOT amend pushed commits or force-push to `master` / `filament-5`.
- Do NOT use heredoc to append to CSS — produces duplications (see `feedback_heredoc_append.md`).
- Do NOT speculatively refactor outside the current task's scope — bounded slice + contract test is the dominant winning pattern in this repo.
- Do NOT introduce unconditional short-circuits (`return true;`, `return false;`) at the top of cache-staleness checks — they bypass TTL and either force continuous rebuilds or pin stale data. Use explicit guards (file existence → readability → age).
- Do NOT reply to pure-ack PM emails — even congratulatory or milestone-marking ones (see `.autodev/CONTRACTS.md` routing rules).
